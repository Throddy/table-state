Чашка, кисть, телефон, тарелка: 25–37 px. Поднос около 55–73 px, человек около 140–165 px, стол около 158×108 px. Для любой foundation-модели это слишком мелко на полном кадре. Обязательный приём: вырезать зону стола и увеличивать в 3–4 раза.

### 1.6 Шум оценки

Bootstrap по кадрам на 39 train-кадрах даёт стандартное отклонение скора около 0.03 (90% интервал бейзлайна 0.44–0.54). Это оценка, не факт. Практический вывод: разница меньше 0.02–0.03 на Public и локально ничего не значит, решения принимаем по совокупности (локально два фолда + Public), а не по одному числу.

## 2. Где лежат баллы

`score = 0.2·AP + 0.16·(q_people + q_hands + q_cups + q_dishes + q_items)`

| Компонент | Вес | Бейзлайн (train) | Цель к вечеру пятницы | Потолок, на который идём |
|---|---|---|---|---|
| AP занятости | 0.20 | 0.746 | 0.97 | 0.985 |
| people | 0.16 | 0.655 | 0.82 | 0.90 |
| hands | 0.16 | 0.586 | 0.70 | 0.80 |
| cups | 0.16 | 0.619 | 0.75 | 0.82 |
| dishes | 0.16 | 0.263 | 0.55 | 0.70 |
| items | 0.16 | 0.000 | 0.45 | 0.65 |
| **Итог** | | **0.489** | **≈0.72** | **≈0.82** |

Лидер сейчас 0.770, пятое место 0.713, финал это топ 5–7 по Private. Цель: 0.72+ к вечеру пятницы и 0.78+ к финалу.

Приоритеты по отдаче на час работы:

1. **occ_prob** (почти бесплатно, +0.04): мягкая вероятность вместо 0/1.
2. **items с нуля** (до +0.10): сейчас 0, любой рабочий детектор телефонов/сумок даёт баллы.
3. **dishes** (до +0.07): тарелки и миски, которых прод-детектор не знает.
4. **hands** (до +0.04): только пропуски, лечится своим детектором на увеличенных кропах.
5. **people** (до +0.04): привязка к столу и фильтр прохожих.
6. **cups** (до +0.03).

Три свойства метрики, о которых нельзя забывать:

- **WAPE это L1.** Оптимальный ответ для строки это медиана, а не среднее. Дробные «0.4 чашки» в ожидании не помогают: если вероятность объекта меньше 0.5, ставим 0, иначе 1. Ложное срабатывание стоит ровно столько же, сколько пропуск. Порог уверенности для каждого класса подбираем так, чтобы precision был не ниже ~0.5 на объект.
- **Качество класса обрезается нулём.** Если модуль по вещам даёт больше ошибок, чем объектов, он хуже нулей. Каждый модуль обязан доказать, что бьёт нули на обоих днях.
- **AP смотрит только на порядок.** Не округляем `occ_prob`, избегаем одинаковых значений.

## 3. Архитектура решения

```
кадры (1718) ──► [B] свой детектор (person/hand/cup/plate/tray/phone/item)  ─┐
              ├► прод-детекции (готовые)                                    ─┤
              └► [C] open-vocab на 4× кропах столов (посуда, вещи, негативы)─┤──► dets/*.parquet (единый формат)
                 [C] VLM по кропу стола: счётчики в JSON ──► rowfeats/*.parquet
                                                                             │
[A] ядро: slots → привязка объектов к столам → контекст ±30 с → признаки строки
                                                                             │
[A] стекер: правила + пороги + логрег (подгонка только на train, 2 фолда по дням)
                                                                             │
                                             постобработка ──► submission.csv
```

Ключевые решения:

1. **Единый формат детекций и единый код привязки к столам.** Треки B и C отдают боксы, привязку и агрегацию делает ядро. Тогда любой источник можно включить и выключить одной строкой конфига.
2. **Увеличенные кропы.** Мелкие объекты ищем на кропе стола ×4, людей на полном кадре или широком кропе.
3. **Контекст по-разному для разных классов.** Чашки, посуда и вещи статичны: медиана по трём кадрам убирает и пропуски, и ложные. Руки двигаются: наивный максимум по соседям на train роняет hands с 0.586 до 0.414, поэтому для рук берём только текущий кадр. Люди: текущий кадр, соседи только как признак для `occ_prob`.
4. **Обучаем детектор не на счётчиках, а на боксах**: aux-боксы (610 штук) + псевдоразметка всех 1718 кадров сильными open-vocab моделями + (если организаторы подтвердят) ручные боксы на кадрах 25–26.10.
5. **Минимум подгоняемых параметров**: не больше 2–3 порогов на класс, всё проверяется на двух фолдах по дням.

| Если человек... | Ему подходит | Почему |

| силён в pandas, геометрии, валидации, аккуратной инженерии | **A. Ядро** | привязка боксов к столам, контекст, стекер, проверка артефактов, сабмиты |

Частные случаи:

- **Один человек много работал с YOLO.** Он берёт B целиком. Это самый нагруженный трек по обучению, и от него зависят hands, cups и people, то есть три счётчика из пяти.
- **Оба умеют YOLO, с VLM не работал никто.** Более опытный в YOLO берёт B. Второй берёт C и начинает с Grounding DINO и OWLv2 (задача C2), это обычные детекторы с текстовым запросом. VLM (C3) остаётся необязательной и запускается только после проверки на train.
- **GPU на 16 ГБ есть только у одного.** Он берёт тот трек, где без GPU нельзя ждать: C с VLM. Обучение небольшого детектора на кропах укладывается в квоту Kaggle.
- **У участника трека C мало опыта.** Максим забирает у него C5 (псевдометки для B), потому что это стыковка форматов, а не моделирование.
- **Никто не работал ни с чем из этого.** Сильнейший по Python берёт B (там больше кода и больше баллов), второй C2 без VLM.

Чего не делать: не делить один трек на двоих и не меняться треками после пятницы 14:00. К этому моменту у каждого уже свои артефакты и кэши, передача съест несколько часов.

## 6. Стратегия сабмитов

- Лимит 10 в день. План: чт-ночь 1–2, пт 6–8, сб 6–8. Два последних слота субботы держим в резерве.
- Сабмитит только A через `tools/submit_gate.py` (валидация формата, карточка сабмита, запись в журнал).
- Каждый сабмит отвечает на один вопрос («включение VLM-вещей помогает?»), а не «попробуем ещё».
- Финальный выбор:
  - `S_safe`: лучший по локальной валидации на обоих днях, с консервативными порогами, без компонент, которые помогали только на Public.
  - `S_bold`: лучший по Public, если локально он не хуже `S_safe` больше чем на 0.01.
- Две финальные отправки отмечаем на Kaggle вручную до 22:30 субботы. Без отметки Kaggle возьмёт лучшие по Public.
- Public это около трети оцениваемых строк. Гнаться за третьим знаком на нём значит переобучиться под ~27 кадров.
